# スタディスポットMAP（プロトタイプ）

無料で勉強できる場所を地図上にピンで並べ、S〜Cのランクと点数、設備、
**時間帯ごとの空き状況**を共有するためのサイトの試作版です。
いまは栃木県のデータのみ入っていますが、都道府県は全国から選べる構造にしてあります。

`index.html` をブラウザで開くだけで動きます（ビルド・サーバー不要）。

---

## 画面

- **最上部** — 都道府県 › 市町村 のセレクタ ＋ 施設名検索。全国から絞り込む入口。
- **左サイドバー** — スコア順のランキング。カードに「開館中／本日の時間」「空きやすい時間帯」「設備タグ」が出る。
- **右** — 地図。ピンはランク色（S=金 / A=緑 / B=青 / C=灰）。ホバーで施設名・点数・本日の時間。
- **起動直後** — 選択中の地域の全スポットが収まるように地図をフィットし、**1位のスポットの詳細を自動で開く**ので、何もクリックしなくても情報が読める状態から始まります。

## 評価指標（8軸）

| 軸 | 重み | 見るところ |
|---|---|---|
| 静音性 | 18% | 私語・アナウンス・生活音 |
| 電源 | 15% | コンセント席の有無と数 |
| Wi-Fi | 13% | 無料Wi-Fiの有無と速さ |
| 座席・机 | 13% | 机の広さ、席数、椅子の質 |
| 人目 | 12% | 画面が見られない／視線が気にならない |
| 空調 | 11% | 夏冬に快適に居られるか |
| アクセス | 10% | 駅近か、駐車場があるか |
| 水 | 8% | 給水機・自販機・水道 |

各口コミで1〜5をつけ、全口コミの平均に重みを掛けて100点換算します。

| ランク | 点数 |
|---|---|
| S 神スポット | 85〜100 |
| A かなり快適 | 72〜84 |
| B 普通に使える | 58〜71 |
| C 条件つき | 〜57 |

軸・重み・閾値は `index.html` の `AXES` / `RANKS` を書き換えるだけで変えられます。

## 時間帯ごとの空き状況

口コミを書くとき「行った曜日（平日/土日）・時間帯・その時の混み具合」を選びます。
その集計が詳細画面のヒートマップになります。

```
        9–11  11–13  13–15  15–17  17–19  19–21
平日    空き   ふつう  ふつう  ...
土日    混雑   混雑    ...
```

- 現在の時間帯のセルは白枠で囲まれます
- カードには「平日9–11時が空き」のように、一番空いている時間帯が出ます
- チップ **「🕐 いま空いてる」** で、今この時間に空いているスポットだけに絞れます
- チップ **「いま開いてる」** は平日/土日の開館時間から判定します（詳細では「開館中／時間外」バッジ）

営業時間は平日・土日祝を分けて持っています（`hoursWd` / `hoursWe` / `closed`）。

## 絞り込み

ランク（S/A/B/C）、種別、市町村、フリーワード、並び順（スコア／遅くまで開いている順／口コミ数／名前）、
設備チップ（電源・Wi-Fi・空調・水・人目・静か・完全無料・いま開いてる・いま空いてる）。

## 地図について（Leaflet ↔ Google Maps）

初期状態では **OpenStreetMap（Leaflet）** で表示します。APIキーなしですぐ見られるようにするためです。

右上「🗺 Google Mapsに切替」から **Maps JavaScript API** のキーを入力すると Google マップに切り替わります。
キーはブラウザの localStorage にだけ保存され、外部には送信しません。

`LeafletAdapter()` と `GoogleAdapter()` が同じインターフェース
（`clear / add / highlight / focus / fit / onMapClick / cursor`）を実装しているので、
どちらか一方に寄せるのも簡単です。

Google Maps を使う場合の準備:

1. Google Cloud Console でプロジェクトを作成
2. **Maps JavaScript API** を有効化（施設情報の自動取得をするなら **Places API** も）
3. APIキーを発行し、HTTPリファラー制限をかける

## データの保存先 — 端末内 / 共有DB

右上のバッジが現在の保存先を示します。クリックすると設定が開きます。

| バッジ | 状態 |
|---|---|
| `端末内に保存` | 未設定。このブラウザの localStorage にだけ保存され、他の人には見えません |
| `☁ 共有DB` | Supabase に接続中。投稿は全員に反映されます |

### 共有DBの繋ぎ方

1. [supabase.com](https://supabase.com) でプロジェクトを作る（無料枠で足ります）
2. SQL Editor に **`supabase-schema.sql`** を貼って実行 → `spots` / `reviews` テーブルとRLSができる
3. Settings › API から **Project URL** と **anon public** キーをコピー
4. 右上「☁ 共有DBの設定」に貼って「接続する」
5. 初回だけ、同じ画面の「サンプルを共有DBに投入する」で中身を入れられます

接続情報はブラウザの localStorage に保存されます（anonキーは公開前提の鍵なのでブラウザに置いて問題ありません）。
接続に失敗したときは自動的に端末内保存にフォールバックし、バッジのツールチップにエラーが出ます。

### スキーマ

- `spots` — 施設名、都道府県/市町村、種別、住所、緯度経度、`hours_wd`（平日）/`hours_we`（土日祝）/`closed_days`、料金、メモ
- `reviews` — `spot_id`、8軸の評価 `ax_quiet` 〜 `ax_water`（1〜5のcheck制約つき）、コメント、`visit_day`/`visit_slot`/`visit_level`（空き状況の元データ）

## データについて（重要）

同梱データは31件で、性質が2種類あります。

- **栃木県内の14件** — 動作確認用のサンプルです。施設名は実在しますが、営業時間・設備・口コミはすべて検証用に作ったもので、実際の状況を保証しません。
- **下野市の17件** — 各施設の公式サイト等で住所・営業時間・休館日・設備を確認して入れた初期データです。**評価は入れていません**（すべて「未評価」）。誰も行っていないのに点数がつくのを避けるためで、最初に行った人の投稿がそのままスコアになります。座標はおおよその位置なので、正確な場所は「Googleマップで開く」から確認してください。

### 「設備」と「評価」は別もの

| | 中身 | 誰が入れる |
|---|---|---|
| **設備** | Wi-Fi / 電源 / 空調 / 水 が **あるか・ないか・不明か** の事実 | 公式情報から確認できたものを初期データとして登録 |
| **評価** | 8軸を1〜5で採点した主観。平均から100点満点とランクを計算 | 実際に行った人の口コミのみ |

ガストやココスのように「無料Wi-Fiがある」と公表されている店は、評価ゼロでも設備として
Wi-Fi あり と表示され、「Wi-Fi」チップの絞り込みにヒットします。
評価が1件も無いスポットはランク欄が **未評価** になり、Cランクとは区別され、一覧では常に末尾に並びます。

**同梱のRLSポリシーは「誰でも読める・誰でも書ける」プロトタイプ用です。**
このまま一般公開するとスパムや荒らしを止める手段がありません。公開前に
`supabase-schema.sql` 末尾のコメントに従って、ログイン必須（`authenticated`）＋承認フローに切り替えてください。

## 本番化するときに残っていること

1. **ログイン** — Supabase Auth の Google ログインが手軽。荒らし・多重投稿対策
2. **モデレーション** — 新規スポットと口コミの承認、通報ボタン（schema.sqlに `approved` 列の雛形あり）
3. **Places API 連携** — 施設名から住所・営業時間・写真・座標を自動補完
4. **写真投稿** — 席の様子・電源の位置が分かる写真は口コミより強い（Supabase Storage）
5. **利用規約** — 商業施設は長時間の居座りがトラブルになりやすいので掲載基準を明記する
6. **ホスティング** — 静的1ファイルなので Netlify / Vercel / GitHub Pages にそのまま置けます
