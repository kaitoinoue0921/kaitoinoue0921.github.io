# まちのコエ（プロトタイプ）

地域住民が自発的にまちのインフラ（公共施設・道路交通・環境など）の課題を共有し、
賛同が集まったら行政提出用の提案書を自動生成する、非営利のシビックテック・プラットフォームの試作版です。

`index.html` をブラウザで開くだけで動きます（ビルド・サーバー不要）。

---

## 画面

- **課題** — カテゴリ・地点つきで投稿された課題の一覧。賛同順／新着順／議論の活発さ順で並び替え
- **地図** — 課題をピンで表示。円の大きさが賛同数
- **投稿** — カテゴリと地点を選んで課題を書く。匿名で公開される
- **透明性** — 今月の寄付額と運営費の内訳、入出金の記帳。理念上、誰でも読める必要があるページ

課題を開くと、賛同ボタン（1人1票、取り消し可）とコメント欄（「意見」と「解決策の提案」を区別）が並びます。
賛同が50件に達すると「行政提出用の提案書を生成（PDF）」ボタンが押せるようになり、
議論の要約を組版した書類をブラウザの印刷機能でPDF保存できます。

## データの保存先

いまは端末内の localStorage にだけ保存されるプロトタイプです。投稿・賛同・コメントは
ブラウザを閉じても残りますが、他の人には見えません。デモデータに戻すには:

```js
localStorage.removeItem('machinokoe.v1'); location.reload();
```

## データモデル（schema.sql）

`profiles / places / issues / votes / comments / proposals / reports / donations / expenses / budget_goals`

設計上のポイントは3つです。

1. **重複投票の防止** — `votes` の主キーを `(issue_id, user_id)` にしてDB層で担保。アプリ側のチェックに依存しません
2. **匿名性** — 氏名・メールは `auth.users` にのみ置き、公開テーブルには通称（住民 A7）しか持たせません
3. **削除させない** — `issues` / `comments` に DELETE ポリシーを作っていません。行政に提出した根拠が後から消えるのを避けるため。不適切な投稿は `hidden` フラグで伏せる運用です

賛同数・コメント数はトリガで非正規化カラムに同期しており、一覧のソートで毎回集計クエリを走らせずに済みます。

## 本番化するときに残っていること

1. **ログイン** — Supabase Auth の Google ログイン。匿名性を保ちつつ重複投票を防ぐ、提案書にあった要件そのもの
2. **地図タイルAPI** — いまは簡易SVG。`places.lat/lng` は用意済みなので差し替えはデータ移行なしでいける
3. **サーバー側PDF生成** — いまは `window.print()`。Edge Function化して `proposals.pdf_url` に保存
4. **決済** — 寄付の受付導線（`donations.provider_ref` で冪等性を担保する設計まで）
5. **通報・モデレーション** — テーブルとRLSのみ用意。伏せる運用のUIは未実装
